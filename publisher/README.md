# Mon · 写作室

私人博客管理平台，服务于 `NN66kk/Mon-Blog`。首页 `/` 是管理中心，`/write` 是写作编辑器。使用 ChatGPT 登录，D1 保存私有草稿、历史版本、回收副本与发布记录，R2 保存未发布图片。GitHub 访问令牌采用 AES-GCM 加密，且仅接受博客所有者 NN66kk 的账号。

## 日常使用

| 入口 | 功能 |
| --- | --- |
| 博客文章 | 同步真实标题和标签；按栏目、标签、关键词筛选；排序、分页；修改已有文章；查看 Git 历史并提取旧版本；删除文章前输入标题确认 |
| 草稿箱 | 新建、搜索、复制、批量移入回收站、选中备份、导入 Markdown；自动保存和版本冲突保护 |
| 写作编辑器 | Markdown/公式/任务列表预览、图片上传及图片库插入、标签与摘要、保留高级 YAML、Ctrl/Cmd+S、查看和恢复草稿历史 |
| 图片库 | 私有图片上传、预览、下载、复制引用、查看草稿引用、筛选未使用图片、归档/恢复；查看博客中已有图片 |
| 发布记录 | 区分新增/更新、删除、恢复；查看提交和构建链接；持续核对部署及实际页面状态 |
| 回收站 | 恢复草稿；把已删除的博客文章恢复到原路径；保留图片，不做物理清理 |
| 设置与备份 | GitHub 连接检查、令牌更新；完整草稿 ZIP 备份，包含回收站草稿及其私有图片 |

手机和窄窗口通过顶部导航访问全部入口；编辑器顶部「文章设置」始终可打开标签、摘要和高级信息。修改博客文章会先打开私有草稿，点击发布后才更新公开博客。博客仍通过 GitHub Actions 构建，保存草稿与公开上线是两个独立状态。

第一次同步会读取文章元数据，后续按 Git blob SHA 使用缓存。已发布文章沿用原路径和栏目，避免旧链接失效。删除只移除文章文件，保留回收副本和原有图片；恢复操作不会覆盖同路径的新文章。

## 本地运行

```powershell
npm install
npm run dev
```

Sites 在开发模式提供本地测试身份；托管环境使用真实登录。部署前先应用 `drizzle/` 迁移。开发数据库可通过 Wrangler 的本地 D1 命令应用同一迁移，禁止向线上数据库运行测试数据。

本轮新增迁移 `0002_mushy_starhawk.sql`：添加草稿历史、文章索引、文章回收副本、图片归档表，以及草稿删除标记和发布动作字段。只增加表、索引和列，保留原草稿及连接。已有站点应在更新代码前应用尚未执行的迁移；不能直接重复执行 `ALTER TABLE`，也不能重建或清空数据库。

## 托管配置

Sites 逻辑绑定在 `.openai/hosting.json`：`DB` 和 `FILES`。运行时还需要一个至少 32 字符的随机 secret `CREDENTIAL_KEY`，用于加密 GitHub 令牌。该密钥不得提交到源码，也不应随意轮换；轮换后需重新连接 GitHub。

保持 Sites 访问范围为仅所有者。进入「连接博客」创建 GitHub 细粒度令牌，仅授权 `Mon-Blog`：Contents 读写，Actions 只读。令牌仅加密存于服务端，不写入浏览器持久化存储。

## 校验

```powershell
npx tsc --noEmit
npm test
npm run build
```

不需要运行博客的 `mkdocs build`。

本地开发服务启动后，可运行 `npm run test:local` 验收登录隔离、草稿版本冲突、历史恢复、回收站和私有图片上传/归档。默认连接 `http://localhost:5173`，可通过 `PUBLISHER_TEST_URL` 指定实际本机地址；测试拒绝非本机地址。该测试会在本地 D1/R2 留下标明用途的验收草稿和图片，不访问 GitHub，也不写线上数据库。

## 发布约定

- 新建草稿与图片保持私有，点击发布后才进入博客仓库。
- 文章与新增图片合并为一次 Git commit，分支推进使用 `force:false`，并检查原文章的 blob SHA。
- 修改旧文保留未知 YAML 字段、Wiki Link、文件路径和首次发布日期；不自动移动栏目。
- 网页预览覆盖普通 Markdown、GFM、公式。HTML 不执行；Wiki Link、Mermaid、MkDocs 扩展以博客最终渲染为准。
- 图片每张最大 5 MB，每次最多 12 张、合计 20 MB。大图在浏览器尝试压缩。
- 发布任务按草稿 ID 与 revision 去重。失败后修正/保存一个新版本再发布；冲突时重新导入最新文章会创建另一份草稿，保留原编辑内容。
- 切换、导入和恢复草稿前先完成当前保存；等待期间锁定编辑及重复切换。保存或读取失败时继续保留当前内容。
- 新文章的首次发布日期仅在确认提交进入博客分支后保存；失败的尝试不会提前占用日期。
- 只有在线文章包含本次 release 标记时才显示「已上线」，构建成功与上线分开记录。
- 文章删除须同时确认包含删除提交的成功构建和公开页面返回 404/410，才显示「已下线」。取消的构建可以由包含该提交的后续成功构建完成。
- 构建被取消后仍检查文章上线情况；同一文章的较新版本已确认上线后，旧任务显示「较新版本已上线」并停止轮询。
- 浏览器自动保存不等于完整离线支持；本地恢复副本仅用于意外中断，且按用户隔离。
- 草稿历史保留服务端保存版本，界面展示最近 100 条；提取历史版本不会自动发布。新功能上线前未记录的草稿历史无法补回。
- 草稿 ZIP 包含所选草稿、原始元数据和引用的私有图片；不包含访问令牌、所有历史修订或整个博客仓库。已有博客内容及图片另由 GitHub 保管。Markdown 可重新导入；ZIP 暂不提供整包一键恢复，解压后的本地图片需重新上传。
- 图片归档保留 R2 对象，且拒绝归档仍被草稿（包括回收站草稿）引用的图片；博客图片当前提供只读浏览，不执行批量清理。

尚未使用真实 GitHub 授权令牌执行生产发布，需要所有者连接账号后完成最后一次端到端验证。

管理平台新增能力、验收结果和上线步骤见 [MANAGEMENT-RELEASE.md](MANAGEMENT-RELEASE.md)。早期编辑器验收记录保存在 [ACCEPTANCE.md](ACCEPTANCE.md)，其中的旧计数和旧界面描述以本轮记录为准。
